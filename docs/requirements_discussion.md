# 食事アルバム Webサービス 要件定義

> 回答を反映した要件定義ドキュメント

---

## 1. サービス概要

毎日の食事写真を記録し、AIによる栄養評価・振り返り・献立レコメンドを提供するWebサービス。
SNS風のデザインで、食事の記録と振り返りを楽しく続けられるUXを目指す。

---

## 2. ターゲットユーザー

| 項目 | 決定事項 |
|------|----------|
| 主なユーザー | 自分用 + 家族・友達にも使ってもらう想定 |
| デバイス | スマートフォン中心（Webアプリ） |
| 技術リテラシー | 一般ユーザー |
| 記録頻度 | 朝・昼・晩の1日3回 + 献立に迷った時にレコメンド利用 |

---

## 3. 主要機能

### 3.1 食事記録機能
- 写真撮影 / アップロード
- 食事日時の記録
- メモ・コメント入力
- 食事分類（朝・昼・夜）

### 3.2 栄養評価機能（AI）
- 写真からの料理・食材認識
- 推定カロリー・栄養素の表示（タンパク質・脂質・炭水化物など）
- 精度: **目安レベル**（種類はある程度細かく、量はざっくり）
- 評価コメント（良い点・改善点）
- 実装: **Claude API** を使用

### 3.3 振り返り機能
- **デイリー・ウィークリー・マンスリー** のサマリー
- 栄養バランスのグラフ・チャート表示
- 食事パターンの分析

### 3.4 献立レコメンド機能
- 不足している栄養素から **食材をピックアップ**
- その食材を使った **レシピ（料理）を提案**
- 「何食べよう？」と迷った時に開いて使える

### 3.5 ログイン・ユーザー管理機能
- ユーザーごとにデータを紐づけて管理
- 認証方式: **メール+パスワード** および **Googleログイン** の2系統
- ユーザー追加・登録機能は後続開発で対応

---

## 4. 技術スタック

| レイヤー | 選定 |
|----------|------|
| フロントエンド | Next.js（React）+ PWA対応（モバイルファースト） |
| バックエンド | Node.js（Express or Hono） |
| データベース | PostgreSQL |
| AI / 画像解析 | Claude API |
| ストレージ | クラウドストレージ（S3等） |
| 認証 | メール+パスワード / Google OAuth 2.0 |
| コンテナ | Docker Compose（フロント・バックエンド・DB の3コンテナ構成） |

### 開発環境（Docker Compose構成）

```
docker-compose.yml
├── frontend   (Next.js / ポート3004)
├── backend    (Node.js API / ポート3005)
└── db         (PostgreSQL / ポート5432)
```

### デプロイ構成

| レイヤー | デプロイ先 | 補足 |
|----------|-----------|------|
| フロントエンド | **Vercel** | Next.jsと最も相性が良い。GitHubにpushするだけで自動デプロイ |
| バックエンド | **Railway** or **Render** | Node.jsアプリを簡単にデプロイ可能。無料〜低コストプランあり |
| データベース | **Railway** or **Supabase** | PostgreSQLをマネージドで提供。バックアップも自動 |
| ストレージ | **Cloudflare R2** or **S3** | 写真の保存先。R2はエグレス無料で安価 |

#### デプロイの考え方
- **開発時**: Docker Composeでローカルに3コンテナを立ち上げて開発
- **本番時**: 各サービスを専用のクラウドサービスにデプロイ
  - Docker Composeはあくまで開発環境用。本番ではマネージドサービスを使うことで、サーバー管理の手間を省く
  - 将来AWSに移行する場合: ECS（コンテナ）+ RDS（DB）+ S3（ストレージ）構成に移行可能

## 5. スコープ

### MVP（まず最初に作るもの）
1. ログイン機能（メール+パスワード / Googleログイン）
2. 食事写真のアップロード・登録
3. 食事の一覧表示（いつ・何を食べたかの振り返り）
4. カレンダービュー

### フェーズ2
5. AIによる栄養評価コメント
6. デイリーサマリー

### フェーズ3
7. ウィークリー・マンスリーの振り返りグラフ
8. 献立レコメンド機能
9. ユーザー登録・追加機能（他の人が自分でアカウントを作れる）

### 将来構想
- ネイティブアプリ化（App Store配布）
- SNSシェア機能

|------|----------|
| デザイントーン | **SNS風**（mixiのようなカジュアルなイメージ） |

---

## 7. 非機能要件

| 項目 | 内容 |
|------|------|
| パフォーマンス | 写真アップロード後、数秒以内にレスポンス |
| セキュリティ | 食事写真・健康データは個人情報として扱う |
| スケール | 当面は個人〜数十人規模 |
| オフライン対応 | 非対応（当面） |
